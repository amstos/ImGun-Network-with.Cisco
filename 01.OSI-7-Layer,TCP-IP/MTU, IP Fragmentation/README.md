# MTU

## 개요

**L2계층에서 한번에 전송할 수 있는 최대 패킷의 크기**를 뜻한다.<br>
IP헤더와 상위데이터의 합산이며 L2이더넷 헤더는 포함되지 않는다.<br>
최대크기는 **1500Byte**이다.

# IP Fragmentation

## 개요

**IP 단편화(IP Fragmentation)** 는 크기가 큰 IP 패킷을 네트워크 전송에 적합한 더 작은 단위(조각)로 쪼개고, 목적지에서 이를 다시 원래 데이터로 재조립(Reassembly)하는 과정이다.

## 송신 측의 IP Fragmentation 과정
L3 계층에서 4000바이트의 데이터를 L2 계층(MTU 1500바이트)을 통해 보낼 때, IP 헤더(20바이트)를 포함하여 다음과 같이 분할된다.

* **첫 번째 패킷:** IP 헤더 (20 Byte) + 데이터 (1480 Byte) = **1500 Byte**
* **두 번째 패킷:** IP 헤더 (20 Byte) + 데이터 (1480 Byte) = **1500 Byte**
* **세 번째 패킷:** IP 헤더 (20 Byte) + 남은 데이터 (1040 Byte) = **1060 Byte**


## 수신 측의 Reassembly 과정
인터넷 망을 거치며 패킷의 도착 순서가 섞이더라도, 목적지 컴퓨터(수신 측 L3 계층)는 IP 헤더의 3가지 핵심 정보를 통해 원본 데이터로 완벽히 복원한다.

* **Identification (식별자):** 분할된 조각들이 원래 하나의 동일한 패킷에서 나왔음을 증명하는 고유 ID이다.
* **Fragment Offset (단편화 오프셋):** 해당 조각이 전체 데이터 중 어느 위치(순서)에 들어가야 하는지 나타낸다..
* **MF (More Fragments) 플래그:** 
  * `1` : 뒤에 이어질 조각이 더 남았음을 의미한다.
  * `0` : 이 패킷이 마지막 조각임을 의미한다.
* **DF (Don't Fragments) 플래그:**
  * `1` : IP 단편화금지를 의미한다. (만약 패킷이 MTU보다 큰데 DF가 1이라면, 라우터는 패킷을 폐기하고 송신자에게 ICMP 에러 메시지를 보낸다..)
  * `0` : IP 단편화가능을 의미한다.


## 단편화의 치명적 단점 (전체 재전송)

조각난 패킷 중 **단 하나라도 네트워크 도중 유실되면, 수신 측은 조립을 포기하고 모아둔 조각을 모두 폐기**합니다. 부분 손실이 **전체 패킷의 재전송**으로 이어져 엄청난 네트워크 비효율(오버헤드)을 초래한다.

현대 네트워크(특히 TCP 통신)는 단편화의 비효율성을 막기 위해, 중간 라우터에서 패킷을 쪼개는 대신 **처음부터 쪼개질 필요 없는 최적의 크기로 맞춰 보내는 방식**을 사용한다.
이때 **DF 플래그**가 핵심 탐지기 역할을 합니다.
1. 송신자는 기본적으로 `DF=1`로 설정하여 패킷을 보냅니다.
2. 중간에 MTU가 작은 라우터를 만나면, 라우터는 단편화를 하지 못하고 패킷을 버린 뒤 **"내 MTU는 OOO바이트니까 줄여서 보내라"**는 에러 메시지를 송신자에게 반환합니다.
3. 송신자는 이 메시지를 통해 경로 상의 최소 MTU를 파악하고, 그 크기에 맞춰 데이터를 다시 전송합니다.
